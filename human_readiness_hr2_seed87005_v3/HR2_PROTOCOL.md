# HR-2 prospective treatment

HR-2 starts from the preserved HR-1 endpoint (`HR1_PARENT.pt`, SHA-256 recorded in `HR2_PROTOCOL.json`) and uses seed 87005. It is a bounded repetition-control treatment: every scientific input and schedule is inherited unchanged from HR-1, while English updates add one fixed recent-token unlikelihood term with weight 0.10 over tokens appearing in the preceding eight input positions. The full-vocabulary causal CE, BOS/EOS and padding masks, batch size, and sequence construction remain unchanged. Binding updates use the established answer CE plus hard-min permutation-invariant localization objective with the existing weight and full T13 scope.

There are exactly 500 updates in 50 cycles of nine English updates then one binding update. The literal HR-1 English and binding schedules are reused byte-for-byte (450 English batches, 50 binding batches). English updates freeze blocks 0–3 and localization/retrieval parameters and train embeddings, blocks 4–7, final norm and language head. Binding restores the full established T13 scope. AdamW remains lr 5e-5, betas (0.9,0.999), eps 1e-8, weight decay 0.05, no scheduler, and gradient clipping 2.0. Deterministic CUDA seed is 87005; no autocast or TF32.

Development evaluation uses only nonsacred development prompts and binding pools at updates 0, 100 and 500. The sealed final readiness battery remains inaccessible. Success requires materially reduced fixed-token and n-gram degeneration while retaining the existing development readiness criteria and both binding pools; decoding penalties alone cannot establish success. HR-1 and Pilot 1 remain preserved comparison checkpoints.
