# Required Corrections — SF2 preflight (before freeze)

Every item below is **mechanical / non-hypothesis-changing**. None alters the treatment's scientific content:
"same SF1 single-fact acquisition run, plus an additive forward-KL-to-frozen-Pilot1 retention term on a separate,
deterministic, ordinary-TinyStories retention pool applied during the 180 English factual updates." No item
requires a new mechanistic experiment, a different treatment, or any access to locked/FINAL/sacred material.

Corrections are already applied in `FROZEN_PROTOCOL_DRAFT.md`.

| # | Type | Correction | Why it is required (ambiguity / risk removed) |
|---|---|---|---|
| M1 | Teacher instantiation | Teacher = a **separate** `DaveLMV082` instance (`build_model("untied")`) loaded only from the parent checkpoint's `base_model.*` keys; `.eval()`, `requires_grad_(False)` on all params; forward only under `torch.no_grad()`; never added to the optimizer; no shared `Parameter` object or storage with the student. | The audit did not state how the frozen Pilot1 teacher is instantiated. Without this, a naive implementation could share parameters with the student or attach the teacher to the optimizer, breaking "gradients reach only student params" and making KL != 0 at update 0. |
| M2 | Retention-pool exact construction | Replace the audit's vague pool rule ("first N rows", "(k*37)%500", "base_offset_k") with the exact no-RNG construction in `FROZEN_PROTOCOL_DRAFT.md` §6: file = `language_train.jsonl` (hash pinned), retain rows with `2 <= len(token_ids) <= 254` in file order, preflight-assert zero token-array equality with the first-128 monitor rows and the 16 SF1 TRAIN prompts, pool `P` = row-major list of all labeled next-token columns, per-update rotation `start = ((u-1)*160) mod |P|`; materialize and SHA-256 the pool before any checkpoint load. | Eliminates the only non-reproducible construction in the proposal. Guarantees ordinary-TinyStories-only content, disjointness from D3 and language-monitor positions and from factual records, and a frozen selection. |
| M3 | KL math pinned | Direction `D_KL(P_student || P_teacher)`; temperature T=1 (no scaling); full 1024-class support; compute `log_softmax` of both logits, accumulate the sum `sum_v p_s(v)*(log p_s(v) - log p_t(v))` in **float64**, cast the final scalar to float32; reduction = **mean over the selected KL positions** (160 per English update) to match the CE term's per-position mean. | Fixes the previously implicit temperature, dtype/precision, and reduction so two implementers produce identical numbers and the lambda=1 scale claim ("both are mean nats-per-position") is literally true. |
| M4 | KL student forward mode | Compute the KL student forward in **eval mode with grad enabled** (dropout off) inside the English update; teacher also eval; then restore `m.train()` and compute the factual CE exactly as SF1. Order within the update: set_scope(English) -> eval-KL forward -> `m.train()` -> factual CE forward -> `loss = CE + lambda_kl*KL` -> single `backward()` -> clip 2.0 -> `step()`. | (a) Matches the eval-mode monitor that defines the language guard and the D3 metric, so the constrained quantity is the quantity being measured; (b) eval forward consumes zero dropout RNG, so the train-mode factual dropout stream is not perturbed relative to SF1's per-update draws (dropout = 0.05 is active in train mode); (c) removes the unspecified-mode ambiguity. |
| M5 | lambda rationale | Keep `lambda_kl = 1.0` as a single fixed value, but replace the audit's "equal counts" rationale with two pre-registered anchors: (1) gradient-scale (`∂KL/∂z_s = p_s - p_t`, O(1) per position, matching the CE per-position gradient); (2) guard/floor (`lambda* = SF1 factual-CE floor ~0.2876 / language-guard allowance 0.25 ~ 1.15`, so 1.0 is within ~13%). Forbid any within-run or post-hoc adjustment. | "Equal counts, therefore 1.0" is not a valid scale argument by itself; CE and forward-KL are different functionals. With the anchors, 1.0 has a defensible prospective rationale, and the pre-registered falsifiers cover both "too weak" (language guard trips at 100) and "too strong" (acquisition guard trips at 100). |
| M6 | New acquisition-guard Boolean | Encode the additive update-100 guard literally as **`if (correct < 10) AND (exact < 10): STOP`**. Keep SF1's endpoint gate all-AND and the language/binding stops unchanged. | The audit's prose ("no better than the parent's 9/16") is only matched by AND. OR would kill a mid-path run that has restored correctness but not yet exact decoding; AND stops only when the run is simultaneously at/below parent on correctness and failing complete answer+EOS. |
| M7 | Fallback fencing | Declare the §11 head-freeze fallback a **separate future experiment** requiring its own freeze and pre-registration. The SF2 harness contains no branch, flag, parameter, or dynamic switch that can select the fallback; it is not implemented. | Prevents accidental automatic execution of a second treatment inside the SF2 run, which would silently turn a one-variable experiment into a two-variable one. |
| M8 | Cadence fidelity | Remove the audit's "checkpoint/evaluation every 25 updates." Keep SF1 cadence exactly: rolling restart every update; permanent checkpoints and evaluations at **0/100/200 only**; add only the frozen D3 diagnostics at 0/100/200 (eval/no_grad). | SF1's checkpoint/evaluation cadence is a listed baseline mechanic that must remain unchanged; adding 25-step evaluations was an unrequested deviation.
